### 一、Imports 导入模块

**模块（module）**：封装了函数、常量等的代码集合。搬进来之后就能用里面的东西。

三个探索模块的工具（⚠️ 这里我一开始记反了，纠正一下）：

| 工具 | 作用 |
| --- | --- |
| `import math` | 把 math 模块导入进来 |
| `dir(math)` | 查看模块内**所有成员**（有哪些函数、常量） |
| `help(math)` | 查看模块的**文档说明**（怎么用） |

导入后用 `.` 访问模块里的内容，例如 `math.pi`、`math.sqrt(2)`。

#### 导入语法（三种）

```python
# 1. 基础导入
import math

# 2. 别名导入（数据分析的通用规范）
import numpy as np
import pandas as pd

# 3. 精准导入（只拿需要的几个）
from math import log, pi
```

> ⚠️ 不推荐 `from math import *`（导入全部）。它容易造成**命名冲突**——如果两个库里有同名函数，后导入的会悄悄覆盖前一个，出了 bug 很难查。

#### 子模块 Submodule
模块内部还可以嵌套子模块，用多层 `.` 逐级访问，例如 `numpy.random.randint(...)`。

### 二、陌生对象排查三件套

拿到一个不认识类型的数据，按顺序用这三招，基本能自己摸清它：

```python
type(obj)          # 1. 它是什么类型？
dir(obj)           # 2. 它有哪些可用的属性和方法？
help(obj.method)   # 3. 某个具体方法怎么用？
```

这套流程的价值在于：**不用死记每个库，随时能现场自查**——这也是为什么前面要先学 `dir` / `help`。

---

### 三、运算符重载 Operator Overloading

同一个运算符（比如 `+`），**作用不固定，由对象的类型决定**：

| 类型 | `+` 的含义 |
| --- | --- |
| 列表 list | 列表拼接（不能和数字相加，会报错） |
| numpy 数组 | 逐个元素相加 |

numpy 数组还有列表没有的能力：

```python
rolls <= 3     # 逐元素布尔判断，返回一整串 True/False
x[1, -1]       # 多维索引（普通列表不支持）
```

---

### 四、底层原理（了解即可，不用深究）

运算符背后其实是在调用**双下划线"魔法方法"**：

```python
a + b     # 等价于 a.__add__(b)
x in lst  # 等价于 lst.__contains__(x)
```

也就是说，一个类型的 `+` 到底怎么算，取决于它自己定义的 `__add__`。这解释了为什么列表的 `+` 和 numpy 的 `+` 行为不一样——它们各自定义了不同的规则。
